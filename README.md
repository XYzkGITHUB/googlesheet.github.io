# Панель спортзала GF Fit

Одностраничный dashboard для мониторинга статистики спортзала.

## Цель 100 абонементов и архив месяцев

Над всеми тремя макетами показана цель месяца: число заполненных имён в
ежедневных вкладках `B6:B25`, прогресс `/100` и небольшой прирост за сегодня.
Для текущего месяца карточка также показывает цель на сегодня, сколько до
неё не хватает и цель на завтра, если сегодня больше не будет продаж.
Цель на сегодня — оставшиеся на начало дня абонементы, разделённые на
оставшиеся календарные дни (включая сегодня), с округлением вверх.
Цель на завтра пересчитывается по текущим продажам и дням после сегодня:
если осталось 10 абонементов на 10 дней и сегодня нет продаж, сегодня
нужен 1, а завтра — 2. В последний день цель на завтра не показывается.
Дата определяется по московскому времени; для других месяцев дневной план скрыт.
Подсчёт абонементов в остальных карточках использует те же строки имён,
поэтому оплаченная строка без имени не увеличивает счётчик.

В исходной Google Таблице создана вкладка **«Архив»** сразу после
`Отчет_Сент_2026`. При создании следующего месяца кнопкой в нижней правой
панели Apps Script добавляет в неё итоговую строку и строки каждого дня:
абонементы, цель, выручку, расходы, прибыль и выручку по категориям.
Затем он копирует пустой шаблон `День 31` в новые ежедневные вкладки.
Существующие дневные и отчётные вкладки не меняются.

Для этой функции нужна **обновлённая версия** `google-apps-script/Code.gs`.
Замените ею код привязанного к таблице проекта Apps Script и создайте новую
версию веб-приложения. Свойство `SHARED_SECRET` сохраняется прежним. На сайте
Netlify установите переменные окружения:

| Переменная | Значение |
| --- | --- |
| `SHEET_BRIDGE_URL` | URL Apps Script веб-приложения с `/exec` |
| `SHEET_BRIDGE_SECRET` | То же значение, что `SHARED_SECRET` |
| `DASHBOARD_ADMIN_TOKEN` | Отдельный длинный ключ для создания месяцев |

При наличии этих переменных сайт читает текущий месяц и архив напрямую через
Apps Script. В правой панели введите ключ администратора и нажмите
«Создать месяц и сохранить архив». Одна операция может выполнить несколько
запросов, чтобы создать все 28–31 дневную вкладку. Если связь прервётся,
повторное нажатие продолжит создание без повторной записи месяца в архив.

Домен `irggorg.ru` сейчас публикуется через GitHub Pages. На нём видны
цель и исправленный подсчёт, но кнопка создания месяцев отключена: GitHub
Pages не выполняет Netlify Functions. Для работы кнопки разверните этот
репозиторий на Netlify с тремя переменными выше. После обновления Apps Script
и Netlify данные архива также появятся в правой панели сайта.

## Сроки абонементов

Внизу привычной карточки «Абонементы» раскрывается блок «Сроки абонементов».
Он показывает истёкшие абонементы, последний день сегодня, окончание в течение
3 и 7 дней, действующие абонементы и общее число записей в реестре.
Дневные показатели, финансовые отчёты, три макета и выбор темы сохранены.

Основные числа читаются из готовых итогов вкладки «Сроки абонементов»
(`A1:F4`); дополнительные — из дат вкладки «Абонементы» (`D4:I`).
Новая функция запрашивает диапазоны без персональных данных. В браузерном
кэше остаются только общие счётчики и дата расчёта. Финансовый загрузчик
пропускает полные вкладки реестра, хранилища и сроков абонементов.

Расчёт использует московскую дату. Последний день действия входит в активные
абонементы, а окна 3 и 7 дней включают сегодня. Продления уже учтены в реестре
таблицы. Если дата итогов устарела или два источника не согласуются, блок
сохраняет исходные итоги с датой, а дополнительные значения показывает как «—».
При ошибке обновления виден последний сохранённый расчёт с предупреждением.
Недоступные данные не подменяются нулями.

Кнопка обновления защищена от повторных запросов; положение страницы
сохраняется. Добавлены состояния фокуса и поддержка уменьшения анимации.
Проверка расчётов: `npm test`.

## Запуск (локально)

```bash
node server.js
```

После запуска открыть:

```text
http://localhost:4173
```

`server.js` теперь только раздает статику из `public/`. Загрузка данных
и хранение годового архива идут напрямую из браузера в Supabase.

## Подключение Google Sheet

Ссылка на таблицу настроена в `public/js/config.js` (`SHEET_SOURCE`).

Для запасного чтения через Supabase и для GitHub Pages таблица должна быть
доступна для чтения без входа:

1. Открыть Google Sheet.
2. Нажать `Поделиться`.
3. Выбрать `Все, у кого есть ссылка`.
4. Права: `Просмотр`.

Если таблица закрыта, сайт показывает демо-данные и предупреждение.

## Supabase (бэкенд)

Запасное чтение работает через Supabase. При подключении Netlify и Apps Script
сайт читает текущий месяц через Netlify Function; сервер Node нужен только
для локальной раздачи статики.

- `supabase/migrations/0001_monthly_archive.sql` — таблица `monthly_archive`
  (замена `data/monthly-archive.json`) с RLS-политиками для анонимного
  чтения/записи (без удаления) — та же модель доверия, что была у старого
  `/api/monthly-archive` эндпоинта.
- `supabase/functions/gym-report` — Edge Function, которая проксирует
  Google Sheet (замена `/api/gym-report` из старого `server.js`). Нужен
  серверный прокси, потому что запрос к `docs.google.com` не проходит
  из браузера напрямую (CORS + разбор HTML вкладок листа).
- `public/js/config.js` — `SUPABASE_URL` и `SUPABASE_ANON_KEY`. Anon key
  безопасно светить в браузере: доступ ограничен политиками RLS, не
  правами ключа.
- `public/js/supabaseClient.js` — клиент `@supabase/supabase-js`
  (подключается прямо с CDN, без сборщика).
- `public/js/api.js` — обращается к Edge Function за отчетом и к таблице
  `monthly_archive` через Supabase REST/JS-клиент.

### Применить схему и функцию к своему проекту

```bash
supabase link --project-ref <ваш-project-ref>
supabase db push                       # применяет supabase/migrations
supabase functions deploy gym-report   # деплоит Edge Function
```

Если нет доступа к CLI/логину проекта — можно вставить содержимое
`supabase/migrations/0001_monthly_archive.sql` в SQL Editor в дашборде
Supabase, а код `supabase/functions/gym-report/index.ts` — в раздел
Edge Functions через веб-интерфейс.

## Архитектура

- `server.js` — локальный статический сервер (только для разработки).
- `supabase/` — SQL-схема и Edge Function (бэкенд в проде).
- `public/js/api.js` — загрузка данных из Supabase.
- `public/js/supabaseClient.js` — инициализация Supabase-клиента.
- `public/js/csv.js` — CSV-парсер.
- `public/js/normalizer.js` — приведение строк таблицы к единой структуре.
- `public/js/analytics.js` — расчет итогов, динамики, сравнений и выводов.
- `public/js/ui.js` — отрисовка интерфейса.
- `public/css/styles.css` — визуальный стиль dashboard.

## Расширение

Новые категории доходов и расходов добавляются через matcher-списки в `public/js/normalizer.js` и подписи в `public/js/ui.js`.
